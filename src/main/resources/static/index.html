01 CONTEXT

검증 컨텍스트

브라우저에 저장되며, 이후 모든 API 호출에 공통으로 사용됩니다.

WHY THIS UI

지금 단계에서 필요한 최소 프론트

예쁜 앱이 아니라, 기록이 실제 행동으로 이어지는지 검증하기 위한 화면입니다.

설명

랜딩 문구로 문제를 이해시키고, 계획 앱이 아니라 복귀 시스템이라는 포지셔닝을 확인합니다.

입력

실패 기록과 재시작 흐름을 직접 눌러보게 만들어, 사람들이 행동을 남길 수 있는지 확인합니다.

결과

Recovery24, TTR, watermark 같은 결과를 같은 화면에 보여줘서, 실제 리포트가 재방문 이유가 되는지 봅니다.

먼저 user와 날짜를 저장한 뒤 설계 단계로 넘어갑니다.

02 PLAN

브레인 덤프

한 줄에 하나씩 입력하면 Inbox Item으로 저장됩니다.

아직 저장된 항목이 없습니다.

아직 선택된 Big 3가 없습니다.

04 TIMEBOX

타임박스 설계

Big 3를 고르면 자동으로 입력 폼이 생성됩니다.

05 RECOVER

타임박스 할당 후 시작 버튼이 보입니다.
실패 이벤트와 재시작 결과가 여기에 표시됩니다.
