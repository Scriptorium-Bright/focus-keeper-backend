01 CONTEXT

누가, 어느 날짜 기준으로 복귀 루프를 검증할지 먼저 고정합니다.

저장된 컨텍스트는 이후 모든 API 호출과 인사이트 조회에 공통으로 사용됩니다.

USER SETUP

검증 컨텍스트

브라우저에 저장되며 다음 방문에서도 유지됩니다.

SCENARIO

오늘의 검증 흐름

1
계획 입력

머릿속 작업을 Inbox로 적고, 오늘 다시 붙잡을 Big 3를 고릅니다.

2
실행 검증

타임박스를 시작하고 실패 체크인과 10분 재시작 흐름을 직접 눌러봅니다.

3
결과 확인

Recovery24, TTR, lastProcessedDate, active alert를 같은 화면에서 확인합니다.

user와 날짜를 먼저 저장하면 나머지 단계가 그 컨텍스트를 그대로 사용합니다.

02 PLAN

복귀를 위한 최소 계획만 남기고 바로 실행 가능한 상태로 만듭니다.

긴 계획표 대신 Inbox, Big 3, 타임박스 세 단계만 유지합니다.

BRAIN DUMP

브레인 덤프

한 줄에 하나씩 입력하면 Inbox Item으로 저장됩니다.

아직 저장된 항목이 없습니다.

TODAY'S FOCUS

오늘의 Big 3

저장된 항목 중 최대 3개를 선택합니다.

Inbox 저장 후 선택할 수 있습니다.
아직 선택된 Big 3가 없습니다.

TIME DESIGN

타임박스 설계

첫 복귀 블록은 정확히 1개여야 합니다.

Big 3를 고르면 자동으로 입력 폼이 생성됩니다.
아직 생성된 타임박스가 없습니다.

03 EXECUTE

실패를 숨기지 않고 바로 기록한 뒤, 가장 짧은 재시작 경로를 확인합니다.

세션 제어와 실패 체크인을 분리해 실제 앱처럼 더 명확하게 보이도록 구성했습니다.

SESSION

세션 제어

타임박스를 시작하고 완료 또는 중단 상태로 바꿉니다.

아직 시작된 세션이 없습니다.
타임박스 할당 후 시작 버튼이 보입니다.

FAILURE & RESTART

실패 기록과 재시작

중단 이유를 남기고 바로 10분 재시작을 만들어볼 수 있습니다.

실패 이벤트와 재시작 결과가 여기에 표시됩니다.
