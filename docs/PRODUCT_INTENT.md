# Product Intent Statement

> Version: v0.3  
> Updated: 2026-03-14  
> Scope: "무엇을, 왜, 누구를 위해 만드는가"에 대한 텍스트 기준선

## 1. 이 문서의 목적

- 기능 목록보다 먼저 제품의 존재 이유를 고정한다.
- 설계/개발/지원서 작성에서 같은 메시지를 유지한다.
- 우선순위 충돌 시 판단 기준으로 사용한다.

## 2. 우리가 하려는 일 (한 문장)

RebootFocus는 "전날 계획이 무너지면 다음날까지 다시 못 붙잡는 직장인을 위해, 놓친 일을 실패 맥락에 맞는 다음 행동과 첫 복귀 블록으로 다시 시작하게 만드는 복귀 코치"를 만드는 프로젝트다.

## 3. 무엇을 위해 만드는가

- 전날 계획 실패가 다음날 무기력과 회피로 이어지는 실행 붕괴를 줄이기 위해
- 사용자가 "다시 해야 하는 걸 아는데 못 시작하는" 상태에서 빠져나오게 하기 위해
- 완료율 중심 관리가 아닌 "복귀율 중심" 실행 시스템을 만들기 위해

핵심 성과 지표:
- Recovery24 (첫 실패 후 24시간 내 재시작률, 메인)
- Recovery48 (첫 실패 후 48시간 내 재시작률, 보조)
- RestartCount24/48 (재시작 강도)
- TTR (Time To Recovery)
- CycleCompletionRate (집중-휴식 사이클 완료율)
- PlanExecutionRate
- EstimationError

## 4. 누구를 위해 만드는가

초기 대상(단일 ICP):
- 25~34세 지식노동 직장인
- 해야 할 일과 마감은 명확하지만, 하루가 한 번 꼬이면 다음날 첫 집중 블록을 다시 못 잡는 사용자
- 캘린더/메신저/노션/투두 앱을 이미 써봤지만 "실패 다음 행동"까지는 도움을 받지 못한 사용자

검증 전 제외 범위:
- 취준생
- ADHD 성향 성인 사용자
- 팀/스터디 운영자 (B2B 라이트)

## 5. 어떤 것을 만들 것인가

핵심 루프:
- Brain Dump -> Big3 -> Timeboxing -> Re-timeboxing

핵심 기능:
- 할 일 수집(Brain Dump)
- 오늘의 Big3 선택
- 시간 블록 배정(Timeboxing)
- 집중 세션 시작/완료/중단 기록
- 뽀모도로/집중 타이머는 핵심 가치가 아니라 복귀 행동을 실행시키는 보조 인터랙션
- 실패 사유 체크인 + 즉시 복귀 액션 제안
- 주간 회고(복귀/실행/예측 오차 피드백)

기능/프로세스 상세 명세:
- `docs/spec/FEATURE_PROCESS_SPEC.md`

## 6. 무엇을 만들지 않을 것인가 (현재 기준)

- 모두를 위한 범용 생산성 앱 포지셔닝
- 초기 단계에서 취준생/ADHD/B2B를 동시에 만족시키는 멀티 세그먼트 설계
- 초기 단계에서 Spark 기반 대규모 분석 파이프라인 기본 경로 도입
- 초기 단계에서 과도한 소셜 기능 확장
- 기준 지표 없이 기술 과시 목적의 인프라 복잡도 증가

## 7. 누구에게 어떤 가치를 제공하는가

사용자 가치:
- 전날 실패가 다음날까지 이어지지 않도록 첫 10분 행동으로 다시 붙잡게 만든다.
- 죄책감이나 의지 문제로 뭉뚱그려지던 실패를 복귀 가능한 행동 단위로 바꾼다.

팀/사업 가치:
- 세그먼트를 선명하게 고정해 메시지, 온보딩, KPI를 한 문장으로 연결한다.
- 복귀 루프 중심 KPI로 제품 개선 우선순위를 명확히 한다.
- 배치/관측/재처리 체계를 통해 운영 신뢰성을 높인다.

채용 포트폴리오 가치:
- 요구사항 정의 -> 구현 -> 테스트/관측 -> 개선의 엔드투엔드 흐름을 증명한다.

## 8. 실행 원칙

- Career-First: 취업 80 / 창업 검증 20
- 세그먼트 확장보다 현재 ICP의 실패 순간을 더 깊게 푼다.
- 기본 경로 단순화: `Spring Batch + RDB`
- 확장 기술(Kafka/Airflow/Spark)은 트리거 근거를 만족할 때만 기본 경로로 승격
- 문서와 코드의 불일치는 즉시 해소

실행 원칙(5단계):
1. 요구사항에 의문 제기
2. 불필요한 과정 삭제
3. 남은 과정 단순화/최적화
4. 사이클 타임 가속
5. 자동화는 마지막에 적용

## 9. 단기 실행 초점 (2026-03-09 ~ 2026-03-23)

- Week 1: Phase 4/5 구현 집중
- Week 2: 테스트/관측/리팩토링 및 트리거 판단 근거 수집
- Week 3: 지원서 제출용 결과물 정리

## 10. 판단 기준 문장

아래 질문에 "예"라고 답하지 못하면 우선순위를 낮춘다.
- 이 기능/변경이 Recovery24(또는 TTR/CycleCompletionRate) 개선에 직접 기여하는가?
- 이 작업이 운영 신뢰성(테스트/관측/복구력)을 높이는가?
- 이 결과를 채용 시장에서 설명 가능한 근거로 제시할 수 있는가?
