# (가칭) RebootFocus 사업계획서 (제안용 v2)

## 1) Executive Summary
- 서비스명: RebootFocus (가칭, 브랜드 충돌 리스크로 명칭 변경 예정)
- 한 줄 소개: 한 번 무너져도 48시간 안에 다시 시작하게 만드는 복귀 코치
- 해결 문제: 계획은 세우지만 시작/지속/복귀가 어려운 실행 격차
- 제안 가치: 집중 완료율이 아니라 이탈 후 복귀율을 높이는 실행 루프 제공
- 수익 구조: Freemium + Premium 구독 + 팀 플랜(후속)
- 주의사항: 유사 상표/상호 여부는 정식 출시 전 법률 검토를 거친다.

## 2) 문제 정의
### 2.1 고객의 실제 문제
- 해야 할 일을 알아도 시작이 늦어짐
- 며칠 실패하면 루틴이 붕괴되고 복귀가 어려움
- 일반 To-do 앱은 기록은 되지만 실행 유지에는 약함
- 번아웃 신호를 조기 감지하지 못해 장기 이탈 발생

### 2.2 기존 대안의 한계
- 할 일 관리 앱: 과제 목록 중심, 행동 루프 설계 부족
- 타이머 앱: 세션은 측정되지만 맥락/회고 연결 부족
- 코칭/커뮤니티: 비용/지속성/개인화 한계
- 단순 To-do: "무엇부터 할지" 결정 부담이 커져 시작 지연 발생

## 3) 타깃 고객
### 3.1 초기 ICP (단일 세그먼트)
- 25~34세 직장인/취준생
- 해야 할 일은 명확하지만 시작 지연과 중도 이탈이 잦은 사용자
- 기존 생산성 앱을 1회 이상 써봤지만 정착하지 못한 사용자

### 3.2 후속 확장 세그먼트 (Phase 2 이후)
- ADHD 성향 성인 사용자
- 팀/스터디 운영자(B2B 라이트)

## 4) 제품 제안 (무엇을 파는가)
### 4.1 핵심 가치 제안
- 단순 타이머가 아니라 실패 다음 행동까지 설계하는 복귀 시스템
- 실패를 없애는 것이 아니라 실패 후 복구 시간을 단축
- 할 일 목록을 시간 블록으로 변환해 실행 마찰을 낮춤
- 개인의 패턴 데이터를 기반으로 다음 행동을 추천

### 4.2 대표 사용자 시나리오
1. 사용자가 Brain Dump로 할 일을 빠르게 쏟아낸다
2. 오늘 Big3를 선택하고 시간 블록(Timebox)을 배정한다
3. 집중 세션 수행 후 성공/실패 체크를 남긴다
4. 실패 시 10분 재시작 블록 또는 더 작은 다음 행동을 제안받는다
5. 주간 회고에서 계획 대비 실제 소요와 복귀 패턴을 확인한다

## 5) 제공 기능 (판매/데모 기준)
### 5.1 MVP 기능 (복귀 엔진)
- Brain Dump 입력(할 일 수집)
- 오늘 Big3 선택
- 타임박싱(언제 할지 시간 블록 배정)
- 집중 세션 기록(시작/완료/중단)
- 실패 사유 체크인 + 10분 재타임박싱/더 작은 다음 행동 제안
- 주간 회고(복귀율, 계획 대비 실행률, 시간 예측 오차)

### 5.2 후순위 기능 (검증 후 확장)
- 팀 플랜
- 공유 결과 페이지
- 딥링크 최적화
- 번아웃 지수 고도화
- 고급 AI 코칭
- 소셜 챌린지 기능

## 6) 비즈니스 모델
### 6.1 수익화 구조
- Free: 기본 챌린지/세션/주간 요약
- Premium: 심화 리포트, AI 회고 고도화, 개인화 코칭
- Team (후속): 팀 단위 대시보드/운영 기능

### 6.2 가격 정책 (가안)
- 월 구독: 9,900원
- 연 구독: 89,000원
- 팀 플랜: 사용자당 월 6,900원(최소 좌석 조건)
- 가격 정책은 실험 기반으로 확정한다(월 9,900원 vs 12,900원 A/B).

### 6.3 매출 가정 방식 (Blended ARPPU)
- 월간제 비중: 60%
- 연간제 비중: 40%
- 월간제 기여: 9,900원 * 0.6 = 5,940원
- 연간제 기여: (89,000원 / 12) * 0.4 = 2,966원
- Blended ARPPU(월): 8,906원

### 6.4 수익 핵심 지표
- Free -> Paid 전환율
- Blended ARPPU
- 월 해지율(Churn)
- LTV/CAC

## 7) 시장 접근 전략 (GTM)
### 7.1 런칭 전
- 랜딩페이지 + 집중 성향 테스트(Web-to-App)로 대기자 모집
- 콘텐츠 채널(숏폼/커뮤니티)에서 문제 공감 메시지 확산

### 7.2 런칭 초기
- 7/14/21일 체험 A/B 테스트로 전환 최적화
- 페이월 노출 시점(온보딩 직후/첫 회고 직후) A/B 테스트
- 실사용 후기 기반 소셜 프루프 확보
- 추천 코드로 사용자 확보 비용 절감

### 7.3 성장 단계
- 공유형 결과 페이지 확장
- 실패 복귀 캠페인(휴면 복귀 시나리오) 운영
- 제휴 채널(스터디/교육/코칭) 테스트

## 8) 운영 지표 (KPI)
### 8.1 제품 지표
- 가입 후 24시간 내 첫 세션 시작률
- 첫 실패 후 48시간 내 재시작률
- 평균 복귀 시간(TTR, Time To Recovery)
- 계획 대비 실행률(PlanExecutionRate)
- 시간 예측 오차(EstimationError)
- D1 / D7 / D30 리텐션
- 주간 회고 열람 후 다음 행동 실행률
- 주간 회고 열람률

### 8.2 사업 지표
- MAU
- 유료 전환율
- MRR
- 해지율
- 고객 획득 비용(CAC)

## 9) 12개월 목표 (가정 기반)
- 3개월: MAU 5,000 / 유료 전환율 3%
- 6개월: MAU 12,000 / 유료 전환율 4%
- 12개월: MAU 20,000 / 유료 전환율 4.5%
- 12개월 MRR 가정치(Blended): 유료 사용자 900명 * 8,906원 = 8,015,400원
- 시나리오 운영:
- Base: 전환율 3.0%, 월 해지율 9%
- Good: 전환율 4.5%, 월 해지율 7%
- Bad: 전환율 2.0%, 월 해지율 12%

## 10) 경쟁/차별화
### 10.1 경쟁군
- 할 일 관리 앱
- 포모도로/집중 타이머 앱
- 코칭 기반 생산성 서비스

### 10.2 차별화 포인트
- 실행 자체보다 "복귀"를 설계한 UX
- 실패 이벤트를 데이터로 해석해 개인화 피드백 제공
- 단기 성취와 중기 리텐션을 동시에 관리하는 루프 구조

## 11) 주요 리스크와 대응
- 리텐션 저하: 실패 복귀 UX와 알림 실험 강화
- 전환율 저하: 무료 구간 가치 재설계, 가격/패키지 A/B 테스트
- 품질 리스크: 핵심 플로우 모니터링 및 장애 대응 체계 고도화
- 신뢰 리스크: 데이터 처리 정책과 고객지원 SLA 명문화
- 법률/브랜드 리스크: 명칭/상표 사전 검토 완료 후 정식 브랜드 확정

## 12) 실행 로드맵 (사업 관점)
1. 복귀 엔진 완성: 시작 -> 실패 체크인 -> 48시간 내 재시작
2. 유료화: 구독 상품과 결제 플로우 확정
3. 성장 채널: 공유/딥링크/추천 강화
4. 운영 고도화: 관측성/실험 체계 구축
5. 확장 검증: 팀 플랜 및 B2B 라이트 모델 테스트

## 13) 제안 문구 (세일즈 피치)
- RebootFocus는 실패 이후 48시간을 관리해 다시 시작을 만드는 복귀 코치 서비스입니다.
- 우리는 집중 시간을 기록하는 앱이 아니라 실행 복귀율을 높이는 시스템을 제공합니다.
